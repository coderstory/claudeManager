### 1.2 M2.16-005-M 限制 (D10 评估顺手修)

- **现状**: `src-tauri/src/services/marketplace_service.rs:85-115` `builtin_repos()` 硬编码 3 个 placeholder URL（占位）。
- **影响**: M2.16 ship 后用户点 marketplace 看到 3 个假 URL 立刻报 bug；M3.4 marketplace 重构的**前提**是内置仓库列表正确。
- **本设计文档交付**: 顺手把 3 个 URL 改成产品拍板的真仓库（占位 fallback + 主 session 可改）。

### 1.3 设计目标

1. **三类 install 语义统一**：内置列表（无 git）/ 第三方仓库（git clone）/ npx 包（无 git 走 npm）。
2. **删除"克隆源码"流程**（清单 12）：第三方仓库不再让用户输密码 clone 源码，而是直接 `git clone --depth=1` 到本地缓存目录，扫描后**用户选资源** install 到 `~/.claude/`。
3. **内置 superpowers + GSD 两个新源**：superpowers 走 `/plugin install` 命令路径（CLI 封装），GSD 走 `npx @opengsd/gsd-core@latest`。
4. **GSD-* 合并展示**：UI 层按 `source_repo` 前缀把 `gsd-*` 合并成 "Get Shit Done" 分类。
5. **过滤规则**：Scanner 层显式屏蔽 `cache` / `node_modules` / `.git` 三个目录（清单 17）。

## §3 重构方案 — 三类 Install 语义统一

### 3.1 三类 Install API

#### (a) `install_builtin(plugin_id: String)` — 内置列表直接装

**用途（清单 13）**: 用户点 superpowers 卡片 → 后端按 `plugin_id` 查 `builtin_repos()` → 调 `/plugin install superpowers@claude-plugins-official` 命令（CLI 封装）→ 落地到 `~/.claude/plugins/superpowers/`。

**与现有 clone 流程的区别**:
- 不需要 git clone（内置列表是官方已发布的 plugin 包，CLI install 命令直接处理下载）
- 不需要"先扫后装"两步（CLI install 一步到位）

**Rust 入口**: `MarketplaceService::install_builtin(plugin_id: &str) -> Result<InstallResult, MarketplaceError>`
- 校验 `plugin_id` 在 `builtin_repos()` 列表里
- 按 `repo.install_cmd`（新增字段）调 `Command::new(...).args(...)`
- 失败 → `Err(Git(...))` 含 stderr

**Tauri Command**: `#[tauri::command] pub async fn install_builtin_plugin(state, plugin_id: String) -> CmdResult<InstallResult>`

**前端包装**: `installBuiltinPlugin(pluginId: string): Promise<InstallResult>`
**UI**: 内置推荐 section 改为**单按钮 "安装"**（去掉 "克隆并扫描" 按钮）。

#### (b) `install_third_party(url: String)` — Git Clone 装第三方仓库

**用途（清单 12 反向解读）**: 用户填第三方 URL → 后端 `git clone --depth=1` → 扫描 5 种 kind → **直接**把扫描到的资源按用户选择 copy 到 `~/.claude/<sub>/`。**不再有"先扫后装"两步**。

**与现有 clone_and_scan 的区别**:
- 现有：`clone_and_scan` 返回 `repo_path` → `install_resource` 再扫一次 → copy。M3.4：单步 `install_third_party(url, selections: Vec<resource_id>)` 一次完成。
- **保留** `clone_and_scan` 作为**纯预览**命令（用户先看仓库里有什么，再勾选 install），向后兼容。

**Rust 入口**: `MarketplaceService::install_third_party(url: &str, selections: Vec<String>) -> Result<Vec<InstallResult>, MarketplaceError>`
- clone → scan → 循环 `install_resource` 对每个 selection → 返回 `Vec<InstallResult>`

**Tauri Command**: `#[tauri::command] pub async fn install_third_party_repo(state, url: String, selections: Vec<String>) -> CmdResult<Vec<InstallResult>>`

**前端包装**: `installThirdPartyRepo(url: string, selections: string[]): Promise<InstallResult[]>`

#### (c) `install_npx(package: String)` — npx 装到 claude plugins 目录

**用途（清单 14）**: 用户点 GSD 卡片 → 后端调 `npx @opengsd/gsd-core@latest --global --silent`（限定全局 / 静默 / 装到 claude plugins 目录）→ 落地到 `~/.claude/plugins/gsd-*/`。

**Rust 入口**: `MarketplaceService::install_npx(pkg: &str) -> Result<InstallResult, MarketplaceError>`
- 调 `Command::new("npx").args([pkg, "--global", "--silent"]).output()`
- 检查 exit code；失败 → `Err(Git(...))`（沿用 `Git` variant 表达外部命令失败）

**Tauri Command**: `#[tauri::command] pub async fn install_npx_package(state, package: String) -> CmdResult<InstallResult>`

**前端包装**: `installNpxPackage(pkg: string): Promise<InstallResult>`

### 3.2 删除"克隆源码"流程（清单 12）

- **现状**：内置推荐仓库 / 第三方 URL 都让用户先 clone 源码（看到 git 弹窗输密码）。
- **M3.4 改造**:
  - 内置列表：直接走 `install_builtin`，**不 clone**。
  - 第三方 URL：保留 `clone_and_scan` 作为**预览**（用户先看有哪些资源），但**生产路径**走 `install_third_party` 单步装。
  - UI 层：把"克隆并扫描"按钮改为"预览资源"（次要操作），主按钮改为"安装"（按所选资源批量装）。

### 3.3 `builtin_repos()` 数据模型扩展

新增字段：
```rust
pub struct MarketplaceRepo {
    pub id: String,
    pub name: String,
    pub url: String,
    pub description: String,
    /// M3.4 新增 — install 模式
    pub install_mode: InstallMode,
    /// M3.4 新增 — install 命令 / 包名（按 install_mode 解释）
    pub install_target: String,
}

pub enum InstallMode {
    /// 走 install_builtin（内置 plugin 的 CLI install 命令）
    Builtin,
    /// 走 install_third_party（git clone 后扫描安装）
    Git,
    /// 走 install_npx（调 npx <package>）
    Npx,
}
```

3 个内置条目（M2.16-005-M 顺手修，placeholder URL → 真 URL）:

| id | name | url | install_mode | install_target |
|---|---|---|---|---|
| `superpowers` | Superpowers (官方) | `https://github.com/anthropics/claude-plugins-official.git` | Builtin | `superpowers@claude-plugins-official` |
| `gsd-core` | Get Shit Done (GSD) | `https://github.com/gsd-build/gsd-core.git` | Npx | `@opengsd/gsd-core@latest` |
| `claude-cookbooks` | Claude Cookbooks (示例) | `https://github.com/anthropics/claude-cookbooks.git` | Git | (空 — 走 url clone) |

> **主 session 拍板提示**: 3 个 URL 是 placeholder fallback，主 session 可改。GSD 走 `npx @opengsd/gsd-core@latest` 已在 `reference/gsd-review-opencode-milestone.md` 记录。

## §4 数据流 — 3 个 Install 场景

### 4.1 场景 A：内置 superpowers (清单 13)

```
[UI] User clicks "安装" on superpowers card
     ↓
[TS] installBuiltinPlugin('superpowers')
     ↓
[Tauri IPC] invoke('install_builtin_plugin', { pluginId: 'superpowers' })
     ↓
[Rust] install_builtin_plugin(State<AppState>, pluginId)
     ├─ state.marketplace_service.install_builtin('superpowers')
     │  ├─ lookup builtin_repos() → find superpowers
     │  ├─ Command::new('claude').args(['plugin', 'install', 'superpowers@claude-plugins-official'])
     │  ├─ check exit code 0 → OK
     │  └─ return InstallResult { installed: true, dest_path: '~/.claude/plugins/superpowers', message: '安装成功' }
     └─ Ok(InstallResult) → Tauri IPC returns to TS
     ↓
[TS] await installBuiltinPlugin resolves → set row state to success
     ↓
[UI] Row shows green banner "安装成功 → ~/.claude/plugins/superpowers"
```

### 4.2 场景 B：第三方仓库 (清单 11 + 12)

```
[UI] User enters https://github.com/foo/bar.git + clicks "预览资源"
     ↓
[TS] cloneAndScan(url)
     ↓
[Tauri IPC] invoke('clone_and_scan', { url })
     ↓
[Rust] clone_and_scan → shallow clone + scan 5 kinds → return ScanResult
     ↓
[UI] Renders resource table — user checks boxes for desired resources
     ↓
[UI] User clicks "安装所选 (3 项)"
     ↓
[TS] installThirdPartyRepo(url, ['plugin/code-review', 'skill/writer', 'command/build.md'])
     ↓
[Tauri IPC] invoke('install_third_party_repo', { url, selections: [...] })
     ↓
[Rust] install_third_party_repo
     ├─ clone (if not cached) + scan
     ├─ for each selection: install_resource(repo_path, selection, options)
     │  ├─ plugin/code-review → copy to ~/.claude/plugins/code-review/
     │  ├─ skill/writer → copy to ~/.claude/skills/writer
     │  └─ command/build.md → copy to ~/.claude/commands/build.md
     └─ return Vec<InstallResult>
     ↓
[UI] Each row shows install success/failure banner
```

### 4.3 场景 C：GSD via npx (清单 14)

```
[UI] User clicks "安装" on GSD card
     ↓
[TS] installNpxPackage('@opengsd/gsd-core@latest')
     ↓
[Tauri IPC] invoke('install_npx_package', { package: '@opengsd/gsd-core@latest' })
     ↓
[Rust] install_npx_package
     ├─ state.marketplace_service.install_npx('@opengsd/gsd-core@latest')
     │  ├─ Command::new('npx').args(['@opengsd/gsd-core@latest', '--global', '--silent'])
     │  ├─ check exit code 0
     │  └─ return InstallResult { installed: true, dest_path: '~/.claude/plugins/gsd-*', message: '安装成功' }
     └─ Ok(InstallResult) → Tauri IPC returns to TS
     ↓
[TS] await installNpxPackage resolves → set row state to success
     ↓
[UI] Row shows green banner "安装成功 → ~/.claude/plugins/gsd-*"
     ↓
[Resource Browser] GSD-* entries grouped under "Get Shit Done" (清单 16)
```

### 4.4 GSD-* 合并展示（清单 16）

- **现状**: GSD 插件可能产生多个子目录 `gsd-discuss` / `gsd-plan` / `gsd-execute` 等，每个在 F16 资源浏览是独立行。
- **M3.4 改造**: Scanner 检测 `gsd-*` 前缀 → `source_repo` 设为 `"Get Shit Done"`（合并分组键）。
- **UI 层**: 资源浏览 source_repo 下拉里显示 "Get Shit Done" 作为分组项，所有 `gsd-*` 归类。
- **不破坏**: 资源浏览列表仍显示所有 gsd-* 子项（用户能逐个 reveal/启用）；分组只在 source_repo 下拉 + 详情面板 "来源仓库" 字段体现。

### 4.5 过滤规则（清单 17）

在 `resource_scanner.rs` `scan_dir_children` 里加显式过滤：

```rust
// M3.4 — 屏蔽常见污染目录（清单 17）
const EXCLUDED_DIR_NAMES: &[&str] = &[
    "cache", ".cache", "Cache",
    "node_modules",
    ".git",
    "__pycache__",
    ".DS_Store",
];
```

- 在 `scan_dir_children` 开头过滤 entry name：
  ```rust
  let name = entry.file_name();
  let name_str = name.to_string_lossy();
  if EXCLUDED_DIR_NAMES.contains(&name_str.as_ref()) {
      continue;
  }
  ```
- 单测：`scan_plugins_dir_excludes_cache_node_modules_git` 验证 plugin 目录下放 `cache/` / `node_modules/` / `.git/` 后扫描不到。

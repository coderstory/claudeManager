# M2.3 — F4 deeplink 导入数据流

> 任务范围：实现 `ccswitch://v1/import?resource=provider&app=claude&name=...&endpoint=...&apiKey=...`
> 单个 provider 配置 deeplink 导入。设计依据：`CLAUDE.md §2.1`（架构先行） +
> `SPEC.md §3.1 F4`。

## 1. 模块分层（CLAUDE.md §3.1）

```
src-tauri/src/
├── infrastructure/
│   └── deeplink_parser.rs     # 纯函数 parse_deeplink_url(&str) → ParsedDeeplink
├── services/
│   └── provider_service.rs    # append import_single_provider (单 provider 写入)
├── commands/
│   └── providers.rs           # append parse_deeplink_url + import_single_provider command

src/
├── lib/api/providers.ts       # append parseDeeplinkUrl + importSingleProvider
└── pages/deeplink-import/     # 真实 UI:输入 URL → 解析 → 模态确认 → 导入
```

**禁止**：
- 业务代码直接调 OS 注册表 API —— 走 `tauri-plugin-deep-link`（CLAUDE.md §3.2）
- 业务代码直接写 provider JSON —— 走 `infrastructure::fs_atomic::write_with_backup`（§7）

## 2. URL 协议（ccswitch v1 简化版）

为对齐 `cc-switch-main` 协议 + 适配本项目 `Provider` 模型（CLAUDE.md §2.3），
只支持 `resource=provider` 单一资源：

```
ccswitch://v1/import?resource=provider&app=claude&name=GLM-4.6&endpoint=https://api.anthropic.com&apiKey=sk-xxx&model=claude-sonnet-4-6
```

字段映射（→ `domain::Provider`）：
- `name` → `Provider.name`（必填）
- `app` → `Provider.provider_type`（必填；只接受 `claude` / `codex` / `gemini` / `openai` / `deepseek` / `custom`）
- `endpoint` → `Provider.api_base`（必填）
- `apiKey` → `Provider.api_key`（必填）
- `model`（可选）→ `Provider.models[0]`
- `notes`（可选）→ `Provider.notes`
- `id`（可选）→ `Provider.id`；缺省时由 name 自动 slug 化（kebab-case + 去重后缀）

## 3. 数据流（两条入口同一终点）

```
场景 A — 冷启动 + deeplink argv（如 Windows 第二次点 ccswitch://...）
  ──────────────────────────────────────────────────────────────
  用户点链接 ccswitch://v1/import?...
    → tauri-plugin-single-instance 拦截 second instance（如果进程在跑）
    → 调用 main 进程的 single_instance handler（lib.rs:32-39）
    → 改写 handler 转发 argv[1] 到 frontend（emit 'deep-link://new-url'）
  或：
    → 进程没在跑 → 直接启动 → tauri-plugin-deep-link 的 on_open_url 监听
    → on_open_url callback 收到 URL → emit 'deep-link://new-url' 到 frontend

  frontend（Tauri webview）
    → 监听 'deep-link://new-url' event
    → 收到 URL 字符串 → invoke('parse_deeplink_url', { url })
    → 拿到 ParsedDeeplink { action: Import, provider: Provider }
    → 弹 Modal（不是 sidebar 路由切换）显示 provider 详情 + 确认按钮
    → 用户点 [确认导入] → invoke('import_single_provider', { provider })
    → Rust 写 `<app_data>/providers/<id>.json` + toast 成功

场景 B — 手动粘贴 URL（开发 / 测试入口）
  ──────────────────────────────────────
  用户在 DeeplinkImportPage 粘贴 ccswitch://... → 点 [解析]
    → 同样调 parse_deeplink_url → 弹模态 → 同样调 import_single_provider
```

## 4. 关键决策

### 4.1 模态而不是路由
deeplink 是事件驱动的（OS 把 URL 推给 app），不是用户主动导航。
走 sidebar 路由会让用户当前任务"被打断"；模态更符合"确认 + 接受/拒绝"模式。

### 4.2 URL 解析是纯函数
`infrastructure::deeplink_parser::parse_deeplink_url(&str) → Result<ParsedDeeplink, AppError>`
不依赖 Tauri runtime / AppState，可单测。`url::Url` 解析做基础校验，ccswitch 业务规则
手写（小、清晰、不引入 sqlparser-style 重型依赖）。

### 4.3 复用 fs_atomic::write_with_backup
单 provider 写入走 `fs_atomic::write_with_backup`（CLAUDE.md §7 写盘前必备份）。
如果文件已存在 → `import_single_provider` 返回 `Err(ProviderError::AlreadyExists)`，
前端弹"已存在，是否覆盖"模态（v1.1 实现覆盖；本迭代做 deny）。

### 4.4 id 自动生成
缺 `id` 时从 `name` 走 `slug` 算法（kebab-case、lower、ASCII only），
重名追加 `-2` / `-3` 后缀（最多尝试 99 次）。SPEC §2.1 要求 id 唯一。

### 4.5 deep-link plugin 事件名
Tauri plugin 实际 emit 事件名是 `deep-link://new-url`（payload = `Vec<String>`）
—— 在 `lib.rs` 的 `setup` 里 `app.deep_link().on_open_url(|event| ...)` 注册。

### 4.6 single-instance argv 转发
修改 `lib.rs:32-39` 的 single_instance handler：扫 argv 找 ccswitch:// 开头的
项，emit `deep-link://new-url` 事件（与 plugin on_open_url 一致）。
不变更 F20 已有行为（focus main window）。

## 5. 写入原子性

```
import_single_provider(provider):
  target = <app_data>/providers/<id>.json
  if target.exists():
    return Err(AlreadyExists(id))
  fs_atomic::write_with_backup(target, serde_json::to_string_pretty(provider))
  return Ok(())
```

Settings.json 不动（F4 导入 ≠ 切换激活）。如果用户想"导入并激活"，M2.5 单独做。

## 6. 失败模式

| 失败 | 表现 | 处理 |
|------|------|------|
| URL 格式错（非 ccswitch://） | `parse_deeplink_url` 返回 Err | frontend 红 InfoBar + 错误码原样 |
| 缺必填字段（name/app/endpoint/apiKey） | `parse_deeplink_url` 返回 Err | 同上 |
| `app` 取值不在白名单 | `parse_deeplink_url` 返回 Err | 同上 |
| id 已存在 | `import_single_provider` 返回 `AlreadyExists` | 弹"已存在"提示 + 不覆盖（v1.1 升级） |
| 写盘失败（I/O） | `import_single_provider` 返回 `Io` | 弹"导入失败" + 完整错误信息 |

## 7. 不做（v1 范围外）

- 不实现 `resource=mcp` / `prompt` / `skill` —— 只 `provider`（SPEC F4 单 provider）
- 不实现 import + activate 一键 —— F4 是导入到 library，激活是 F2 范围
- 不做"覆盖已存在" —— 显式 v1.1 TODO
- 不实现 usage_script / config / config_url 字段（v3.9+ cc-switch 扩展）

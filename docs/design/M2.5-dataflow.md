# M2.5 — F6 MCP 管理 数据流

> 版本：M2.5 — F6 MCP 管理
> 状态：设计完成（实现跟随本文件）

## 业务定义（F6）

用户进入 "MCP 管理" 路由 → 读 `~/.claude/mcp.json`（如不存在 → 显示空状态）→ 看到所有 MCP server 列表 → 可启用 / 禁用 / 新增 / 编辑 / 删除 / 从剪贴板导入。

### 功能要求

1. **列表**：从 `~/.claude/mcp.json` 读 `mcpServers` 映射（McpServer[] 形式），每行显示：name / enabled toggle / command 或 url / args / env。
2. **启用 / 禁用 toggle**：点击 checkbox 立即调 backend toggle，乐观更新 + 失败回滚 + toast。
3. **新增 MCP server**：模态表单（name / type stdio|http / command|url / args / env / enabled），提交后调 `add_mcp_server` command。
4. **编辑 + 删除**：模态表单预填当前值；删除弹 confirm 确认。
5. **从剪贴板导入**：一键读 `navigator.clipboard.readText()` → 调 `parse_mcp_deeplink(url)` → 填入表单（让用户点确认再写入）。
6. **安全 scope**：`mcp.json` 路径必须 `starts_with(~/.claude/)`（M2.4 已有 `resolve_claude_path` 模式）。

## 数据流

```
User click sidebar "MCP 管理" → setView('mcp-management')
  → McpManagementPage mount
  → useEffect → invoke('list_mcp_servers') → Vec<McpServer>
  → 列表渲染（每行：name + enable checkbox + command/url + 编辑/删除 按钮）
  → 空状态（mcp.json 不存在 或 mcpServers 为空）→ 显示"未配置 MCP server" + 引导按钮

点 toggle 启用/禁用:
  → 乐观更新本地 state（McpServer.enabled = !enabled）
  → invoke('toggle_mcp_server', { id, enabled: newValue })
  → 成功: toast "已<启用/禁用> <name>"
  → 失败: 回滚 toggle + toast "错误: <msg>"

点 "新增":
  → 打开模态表单（清空）
  → 填 name / type / command / args / env / enabled
  → 点确认 → invoke('add_mcp_server', { server })
  → 成功: 关闭模态 + 列表追加 + toast "已新增 <name>"
  → 失败: 保留表单 + InfoBar 显示错误

点 "编辑":
  → 打开模态表单（预填当前 McpServer）
  → 修改 → 调 invoke('update_mcp_server', { id, server })
  → 成功: 关闭模态 + 列表更新 + toast "已更新 <name>"

点 "删除":
  → window.confirm("确认删除 MCP server '<name>'?")
  → invoke('remove_mcp_server', { id })
  → 成功: 列表移除 + toast "已删除 <name>"

点 "从剪贴板导入":
  → navigator.clipboard.readText() → 拿到 url
  → invoke('parse_mcp_deeplink', { url })
  → 拿到 ParsedMcpDeeplink { server: McpServer | null }
  → 打开模态表单（预填 server 字段）
  → 用户点确认 → 走 add_mcp_server 流程

打开 mcp.json 文件: ~/.claude/mcp.json
写入: 通过 fs_atomic::write_with_backup（备份 + 原子 rename）
保留其他字段: 读为 Value → 修改 mcpServers → 写回（不丢任何 key）
```

## 设计原则

### Why McpService as separate service (not extension of ProviderService)
- **MCP 配置 vs Provider 配置** 是两个不同的域：Provider 是 Claude API 切换；MCP 是子进程 server 配置。
- M2.4 的 `commands::fs` 已经有 `read_file` / `write_file_atomic` 通用命令，但 **业务级 list/toggle/add/update/remove** 是 MCP 域的逻辑，必须封到 service 层。
- ProviderService 已经在 `provider_service.rs` 里 1000+ 行；MCP 不应该挤进去。

### Why mcp.json (not provider-style per-file)
- Claude Code 的 MCP 配置 **官方** 就是一个 `mcp.json` 文件，含 `mcpServers` 映射。
- 用户心智模型："我所有 MCP server 在一个文件里"，与 Provider 的 "每个 provider 一个 .json" 不同。
- 读写都用 `mcp.json` 一个文件，atomic write 简单清晰。

### Why Defer "保留其他字段" via Value-level patch
- mcp.json 可能含 mcpServers 之外的字段（如 `preferences`、注释、用户自定义 key）。
- 我们的 list/add/update/remove **只**修改 `mcpServers` 字段；其余 key 用 `serde_json::Value` 读 + 修改 + 写，**零丢失**。
- 模式与 M2.1 的 `ProviderService::switch_provider` 写 settings.json 一致（已 ship 且覆盖测试）。

### Why Toggle 是乐观更新 + 失败回滚
- 用户对响应延迟敏感（toggle 应当 < 100ms 反馈）。
- 写 mcp.json 是 sub-second 操作；失败主要在 disk full / permission 异常场景。
- 失败时回滚 + toast 错误，UX 不丢。

## 兼容性

- mcp.json **不存在** → list 返回 `[]`，UI 显示空状态。点击"新增"会创建 mcp.json。
- mcp.json **格式异常** → list 返回 `[]` + InfoBar 警告 "mcp.json 解析失败: <reason>"。不抛错（CLAUDE.md §7）。
- mcp.json **有 mcpServers 之外的 key** → 全部保留（不破坏用户数据）。
- mcpServers entry **缺少 enabled 字段** → 默认为 true（MCP server 默认启用，符合 Claude Code 默认行为）。
- mcpServers entry **缺少 command / url** → 该 entry 默认 disabled，InfoBar 提示 "MCP server '<name>' 配置不完整"。

## 安全

- `mcp.json` 路径必须 `starts_with(<home>/.claude/)`。
- 写入操作走 `fs_atomic::write_with_backup`（CLAUDE.md §7）。
- 不允许 `..` 路径穿越（fs.rs 的 `resolve_claude_path` 已有保护）。
- 读 deeplink URL 时严格 `url::Url::parse`，避免 URL 注入。

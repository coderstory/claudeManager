# M2.6 — F13 备份与恢复 数据流

> 版本：M2.6 — F13 备份与恢复
> 状态：设计完成（实现跟随本文件）

## 业务定义（F13）

用户进入 "备份与恢复" 路由 → 读 `~/.claude/` + `<app_data>/backups/` 下所有 `*.backup.*` 文件 → 显示时间线（按时间倒序）→ 可点任一备份查看完整内容 / 与当前对比 / 一键回滚。

### 功能要求

1. **时间线列表**：扫描所有 `*.backup.<ts>` 文件，按 ts 倒序。每条显示：时间戳（`YYYY-MM-DD HH:MM:SS`）/ 关联文件名 / 文件大小 / 触发来源（settings.json 切换 / claude.json MCP toggle / 用户编辑 / 手动触发）。
2. **详情查看**：点某条 → 调 `read_backup_content` → 在右侧详情面板显示 JSON 原文（可滚动，等宽字体）。
3. **字段级 diff**：选 2 条 → 调 `diff_backups` → 字段级 diff（路径 / Add / Remove / Change）→ UI 渲染绿/红高亮。
4. **一键回滚**：选 1 条 → 弹二次确认 → 调 `restore_backup` → 原子还原。**回滚前先备份当前文件**（双保险 — 防回滚错把对的弄错，CLAUDE.md §7）。
5. **手动触发备份**：UI 上 [立刻备份] 按钮 → 立刻生成一个新的 .bak 文件。

## 数据流

```
User click sidebar "备份与恢复" → setView('backup-restore')
  → BackupRestorePage mount
  → useEffect → invoke('list_backups') → Vec<BackupEntry>
  → 时间线渲染（每条：ts + 关联文件 + 大小）

点某条 backup:
  → invoke('read_backup_content', { path })
  → 右侧详情面板显示 JSON 原文

选 2 条 + [对比]:
  → invoke('diff_backups', { path1, path2 })
  → Vec<DiffEntry> { path, op, old, new }
  → UI 渲染 diff（绿/红高亮）

点 [回滚]:
  → 弹二次确认（"这将覆盖当前 settings.json，是否继续？"）
  → 用户确认 → invoke('restore_backup', { backupPath })
  → Rust:
    1. 读 backup content
    2. 写当前文件前先备份当前（双保险）
    3. 原子 write_with_backup
  → toast "已回滚到 <ts>"

点 [立刻备份]:
  → invoke('backup_now', { kind: 'settings' | 'claude' })
  → Rust: 读当前文件 → 写一个 .bak.<ts>
  → refresh 列表
```

## 模块边界

### Rust side

- `src-tauri/src/infrastructure/backup_scanner.rs` (新建)
  - `BackupEntry` struct — `path: PathBuf` / `original_path: PathBuf` / `timestamp: DateTime<Utc>` (or unix) / `size_bytes: u64` / `source: BackupSource`
  - `BackupSource` enum — Settings | Claude | Manual | Unknown
  - `scan_backups_in(dir: &Path) -> Result<Vec<BackupEntry>, AppError>` — 扫 *.backup.* 文件 → 解析 ts → 排序 → 返回
  - 支持 2-3 种 backup 文件名变体（`*.bak.<ts>` 主流 + 兼容老版本 `*.backup.<ts>`）
  - 5+ 个 inline TDD 测试

- `src-tauri/src/infrastructure/json_diff.rs` (新建)
  - `DiffEntry` struct — `path: String` / `op: DiffOp` / `old: Option<Value>` / `new: Option<Value>`
  - `DiffOp` enum — Add | Remove | Change
  - `diff_json(old: &Value, new: &Value) -> Vec<DiffEntry>` — 递归对比：对象逐 key，数组逐 index，标量直接比
  - **不引入 json-patch crate**（CLAUDE.md §2.3 版本锁，新 dep 必须有理由）。手写简单 path-based diff 即可
  - 6+ 个 inline TDD 测试

- `src-tauri/src/services/backup_service.rs` (新建)
  - `BackupService { paths: AppPaths }`
  - `list_backups() -> Vec<BackupEntry>` — 合并 `~/.claude/` 和 `<app_data>/backups/` 两个扫描源
  - `read_backup_content(path: &Path) -> Result<String, AppError>` — 读 backup 文件
  - `diff_backups(path1: &Path, path2: &Path) -> Result<Vec<DiffEntry>, AppError>` — 读 2 个 → 解析 → diff
  - `restore_backup(backup_path: &Path) -> Result<(), AppError>` — **回滚前先备份当前** → 原子写
  - `backup_now(kind: BackupKind) -> Result<BackupEntry, AppError>` — 手动触发备份
  - 7+ 个 inline TDD 测试

- `src-tauri/src/commands/backup.rs` (新建)
  - 4-5 个 `#[tauri::command]` 包装（list / read / diff / restore / backup_now）

- `src-tauri/src/app_state.rs` (扩展) — 加 `backup_service: Arc<BackupService>`

- `src-tauri/src/lib.rs` (扩展) — invoke_handler 加 4 个新 command

## 安全 scope

- 备份文件路径必须 `starts_with` 平台允许的 2 个目录之一（`~/.claude/` 或 `<app_data>/backups/`）
- 回滚时也必须验证 backup_path 在允许目录里 — 防止 frontend 传任意路径读 `C:\Windows\...`

## 已知妥协（不阻塞 ship）

- 备份触发原因（source）的解析用启发式（看 backup 文件名后缀 / 看同目录其他 .bak 是否含特定 token），M2.6 不做精确归因（需要持久化元数据 sidecar 文件）。SPEC §6.9 提到的 "自动备份（应用启动时）" 标记在 M2.7 之后再做。
- diff 超过 5 层深度返回 summary（"too deep to diff, use external tool"） — 防大文件卡 UI。

## §1 背景与目标

### §1.1 触发问题

**用户反馈 清单 23**："欢迎页改造为项目切换（用户 / 项目双模式）"。

当前 M2.x 的所有 plugin（Provider / MCP / Optimizer / Backup / Marketplace）都隐式绑定到 **用户级** `~/.claude/`：
- `ProviderService` 读 `~/.claude/settings.json`
- `BackupService` 扫描 `~/.claude/*.bak.<ts>` + `<app_data>/backups/`
- `OptimizerService` 扫描 `~/.claude/settings.json` + `~/.claude.json`
- `MarketplaceService` 把资源克隆到 `~/.claude/<subdir>/`

当用户在多项目间切换（公司项目 / 个人副业 / 客户交付）时，每个项目都有自己的 `.claude/` 目录（`.claude/settings.json` / `.claude.json`），M2.x 没办法在它们之间切换 —— 只能手动编辑路径或在不同项目里反复 `cd`。

### §1.2 设计目标

引入 **"项目" 一级抽象**：
- **用户级**（`is_system = true`，不可删）= 现有 `~/.claude/` 行为，完全向后兼容
- **项目级** = 指向任意 `<root_dir>/.claude/` 的虚拟视图。切换项目后，所有 plugin 自动重定向到该项目下的 `.claude/`
- 切换走 **F13 备份 → 原子更新 `current_project_id` → plugin reload**（CLAUDE.md §7 内存/状态纪律）
- 用户级不能删除（保证向后兼容 + M2.x 测试数据不丢）

### §1.3 与现有架构的对齐

| 条款 | M3.10 适配 |
|---|---|
| CLAUDE.md §3.1 分层架构 | 新增 `domain/project.rs`（无 I/O 实体）+ `services/project_service.rs`（业务逻辑） |
| CLAUDE.md §3.2 OS 抽象接口 | `IPlatformPaths` 新增 `active_root_dir()`，业务代码继续通过 `AppPaths` 间接获取 |
| CLAUDE.md §5.3 三层测试 | 单测（domain + service）+ 集成测（5 commands）+ UI e2e（项目切换器） |
| CLAUDE.md §7 内存/状态 | 切换走 F13 备份 + 原子 rename `projects.json` |
| CLAUDE.md §8 subagent 派遣 | 主 session 收报告不亲自执行（auto 模式豁免同步） |

## §2 数据模型

### §2.1 Rust struct 草案（`src-tauri/src/domain/project.rs`）

```rust
use std::path::PathBuf;
use serde::{Deserialize, Serialize};
use uuid::Uuid;

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub struct Project {
    /// 唯一 ID（v4 UUID，由 ProjectService::add_project 生成）。
    /// 用户级项目固定为 SYSTEM_PROJECT_ID。
    pub id: Uuid,
    /// 显示名（用户可编辑）。约束：非空 + ≤ 64 字符。
    pub name: String,
    /// 项目根目录（绝对路径）。用户级 = home（不存 .claude 子路径）。
    /// 项目级 = `<root_dir>`，业务代码拼 `<root_dir>/.claude/settings.json`。
    pub root_dir: PathBuf,
    /// Unix 秒（与 `Provider::created_at` 对齐，避免引 chrono）。
    pub created_at: i64,
    /// `true` = 用户级，特殊，不可删除。M3.10 启动时若 projects.json
    /// 不存在 → 自动种入 1 个用户级项目。
    pub is_system: bool,
}

/// 用户级项目的固定 UUID。M3.10 启动时若 projects.json 不存在或不含此 ID，
/// 自动种入（保证向后兼容 —— M2.x 用户的所有 plugin 数据归属这个项目）。
pub const SYSTEM_PROJECT_ID: Uuid = Uuid::nil();
```

### §2.2 持久化结构（`<app_data>/projects.json`）

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct ProjectsFile {
    /// 文件格式版本（M3.10 = 1）。M3.11+ 加字段时 bump。
    pub version: u32,
    /// 当前激活的项目 ID。None = 尚未初始化（启动时自动 fallback
    /// 到用户级）。
    pub current_project_id: Option<Uuid>,
    /// 所有项目（含用户级）。至少 1 个用户级项目存在。
    pub projects: Vec<Project>,
}
```

### §2.3 `is_system` 语义

| `is_system` | 含义 | 可删？ | `root_dir` 含义 |
|---|---|---|---|
| `true` | 用户级 = 现有 `~/.claude/` | 否 | `home` 目录（**不是** `~/.claude/` 本身 —— 让 plugin 自己拼） |
| `false` | 项目级 | 是 | `<root_dir>`（**不**包含 `.claude` 后缀） |

**业务代码解析当前生效配置时**：
- 用户级 → 读 `<root_dir>/.claude/settings.json` = `~/.claude/settings.json`（M2.x 路径完全不变）
- 项目级 → 读 `<root_dir>/.claude/settings.json`

### §2.4 trait 集成点

`IPlatformPaths::active_root_dir()` 的语义：
- 返回 `Option<PathBuf>` —— `Some(path)` = 当前激活项目级 / `None` = 用户级
- 默认实现 = `None`（向后兼容：M2.x 不感知 projects.json 时，永远走用户级）
- Windows 实现 = 读 `<app_data>/projects.json` + 查 `current_project_id` 对应的 `root_dir` → `Some/None`
- macOS 实现（compile-only stub）= `None`

## §3 trait 变更草案

### §3.1 修改 `IPlatformPaths`

```rust
pub trait IPlatformPaths: Send + Sync {
    fn resolve(&self) -> AppPaths;
    fn ensure_dirs(&self) -> Result<(), PlatformError>;

    /// M3.10 — 当前激活项目根目录。
    ///   - `None` = 用户级（`~/.claude/`）
    ///   - `Some(p)` = 项目级（业务代码读 `p.join(".claude")`）
    ///
    /// 默认实现 = `None`，保持向后兼容。M3.10 Windows 实现会读
    /// `<app_data>/projects.json` + 查 `current_project_id` 对应的
    /// `root_dir`。
    fn active_root_dir(&self) -> Option<PathBuf> {
        None
    }
}
```

### §3.3 `AppPaths` 不变（关键决策）

**为什么 `AppPaths` 不加 `active_root_dir` 字段**：
1. `AppPaths` 在 `setup()` 时一次性解析并 `manage` 到 Tauri State。`active_root_dir` 需要读 `projects.json`，而项目切换是 **运行时** 操作（用户在 UI 里点切换）。两者生命周期错位。
2. 把 `active_root_dir` 留给 `IPlatformPaths` trait method（每次调用实时读），业务代码通过 `state.paths` + `runtime::paths().active_root_dir()` 组合获取。
3. 切换项目时不需要 reload `AppPaths` —— 只需要更新 `projects.json` + 让 plugin 重新调用 trait 方法。

## §4 数据流（3 个核心场景）

### §4.1 场景 (a) 启动 → 加载当前项目

```
lib.rs::run() → setup()
  → platform::init_for_runtime()
  → AppState::build()
    → runtime::paths().resolve() → AppPaths (不变)
    → ProviderService::new(paths) (不变)
    → ProjectService::new(paths) ← 新增
  → app.manage(state)

用户点 sidebar 任一 plugin：
  → list_providers(state)
    → provider_service.list_providers()
      → paths.settings_json = ~/.claude/settings.json  (M2.x 行为不变)

  // 如果用户已切换到项目级，plugin 需读 active_root_dir：
  → list_providers_in_active_root(state)
    → runtime::paths().active_root_dir() → Some("D:/proj-a/.claude")
    → 读 Some(".claude").join("settings.json")  (项目级)
```

**关键点**：M3.10 引入后，`AppPaths::settings_json` 仍指向用户级。Plugin 需要 `active_root_dir()` 时单独调用（这是 M3.x 后续 plugin 适配的范围）。

### §4.2 场景 (b) 用户切换项目

```
用户在 sidebar 顶部下拉选 "Project B" → invoke('switch_project', { id })
  → commands::project::switch_project(state, id)
    → project_service.switch(id)
      1. load_projects() → 读 projects.json
      2. 校验 id 存在 + 不是当前
      3. // 走 F13 备份（CLAUDE.md §7）—— 备份当前 settings.json + .claude.json
         backup_service.backup_now(settings_json)
         backup_service.backup_now(claude_json)
      4. // 原子切换 current_project_id
         projects.current_project_id = Some(id)
         write_projects_atomic(projects) // fs_atomic::write_with_backup
      5. // emit event 让前端 reload plugin state
         app.emit("project-switched", id)
    → Ok(())
  → 前端收到 'project-switched' → 触发各 page 的 useEffect refresh
  → 后续 list_providers / list_mcp_servers 等会走 active_root_dir 自动重定向
```

**关键点**：切换 = F13 备份 + 原子更新 `current_project_id` + event emit。**不**重新解析 `AppPaths`，**不**重启进程。

### §4.3 场景 (c) 用户新增项目

```
用户点 sidebar "新建项目" → 弹输入框（项目名 + 选择根目录）
  → 用户输入 + 选定目录 → invoke('add_project', { name, root_dir })
  → commands::project::add_project(state, name, root_dir)
    → project_service.add(name, root_dir)
      1. 校验 name 非空 + ≤ 64 字符
      2. 校验 root_dir 是绝对路径 + 存在 + 包含 .claude/ 子目录
         // 弹错误 "所选目录不含 .claude/，不是合法 Claude 项目"
      3. 生成 id = Uuid::new_v4()
      4. // 不切换 —— 用户手动切
         projects.projects.push(new_project)
         write_projects_atomic(projects)
    → Ok(new_project)
  → 前端收到新项目 → 刷新下拉列表（不切换）
```

**关键点**：新增项目只追加列表，不自动切。切是用户的显式动作（场景 b）。

## §7 关键决策记录

1. **`active_root_dir()` 返回 `Option<PathBuf>` 而非 `AppPaths`** —— `AppPaths` 在 setup 一次性解析，`active_root_dir` 必须运行时查询。两者生命周期错位。
2. **`is_system` 项目存于 `projects.json`** —— 而非 hardcoded。允许未来"用户级"变成"项目级"（如果产品决定）但当前 UI 不暴露这个动作。
3. **切换项目 = F13 备份 + 原子更新** —— 严格走 CLAUDE.md §7 内存/状态纪律。任何项目切换都有 F13 backup trail，可回滚到切换前状态。
4. **新增项目 = 不自动切换** —— 用户显式切。避免误操作（自动切可能让用户当前页数据丢失感）。
5. **M3.10-arch 不交付 plugin 适配** —— 只交付"切换器"骨架 + 项目管理数据。Plugin 实际读 active_root_dir 在 M3.11~M3.15 完成（13 个适配点列表见 §5）。
6. **macOS 实现 = compile-only stub** —— D6 决策 Mac 真机验证暂缓，macOS `active_root_dir` 直接返回 `None`（永远用户级）。M4 启动前再问。
7. **UUID 复用现有 dep** —— `uuid 1.23.3` 已在 Cargo.toml（CLAUDE.md §2.3 版本锁），不引入新依赖。

## §8 失败模式

| 场景 | 当前行为 | M3.10-arch 行为 | 备注 |
|---|---|---|---|
| 启动时 projects.json 不存在 | 不存在 | 自动种入"用户级"项目 + 设为当前 | 向后兼容 |
| projects.json 损坏（JSON parse fail） | 不存在 | 自动备份坏文件到 `.corrupt.<ts>` + 种入默认 | 防丢数据 |
| current_project_id 指向不存在的项目 | 不存在 | fallback 到用户级 + log warn | 防孤岛 |
| 用户尝试删 is_system=true 项目 | 不存在 | 拒绝 + ErrorBanner "用户级不可删除" | SPEC §6.5 |
| 切换项目但 active_root_dir 不存在（用户删了 .claude/） | 不存在 | 拒绝切换 + ErrorBanner | 防误操作 |

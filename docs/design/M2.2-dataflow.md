# M2.2 — F3 .sql 导入数据流

> 目的：解析 cc-switch 导出的 SQLite dump（`INSERT INTO providers ...` + `INSERT INTO mcp_servers ...`）→ 预览 → 批量导入到 `~/.claude/providers/*.json`。
>
> 参考实现：`D:\project\cc-switch-main\src-tauri\src\commands\import_export.rs` + `D:\project\cc-switch-main\src-tauri\src\database\backup.rs`。

## 4. 关键设计决策

### 4.1 解析策略：手写 regex，不用 sqlparser crate
**理由**：CLAUDE.md §2.3 禁依赖乱加 + cc-switch 导出格式固定（只有 INSERT INTO providers / mcp_servers），不需要完整 SQL 解析器。手写 regex 解析 INSERT VALUES 更可控、可测、易理解。

### 4.2 写盘：write_with_backup（M2.1 已有）
**理由**：CLAUDE.md §7 写盘前必备份。`Provider::to_json_file` 是非原子的（CLAUDE.md §3.1：所有原子写都走 fs_atomic）。但单文件（`<id>.json`）用户不会编辑 + 已写就写完整了，所以用 `fs_atomic::write_with_backup` 保证幂等 + 备份。

### 4.3 去重：按 id 跳过已存在
**理由**：用户重复导同一个 SQL 不应产生重复 provider 文件。`imported` 数 = 实际新写盘数；`skipped` 数 = 已存在。

### 4.4 Preview 复用 parse_sql_dump
**理由**：preview 与 import 用同一函数，避免"preview 通过但 import 失败"的不一致。结果确定性 = 同一输入必产生同一输出。

### 4.5 错误恢复：ImportResult 永远不抛
**理由**：部分行解析失败（如 5 个 provider 4 个成功 1 个字段缺失）是**预期内**的，不能让整个 import 崩。`errors: Vec<SkippedLine>` 把失败的行号 + 原因一起返回给 UI，UI 详情展开。

### 4.6 McpServer 仅预览
**理由**：M2.2 主线是 F3 .sql 导入 provider。MCP 写入 `~/.claude.json` 是 F6 范畴（M2.3+）。M2.2 做最小可用：parser 解析 → preview 展示 → **不**写入磁盘。Commit 信息明确标注"MCP 仅预览，待 F6 落地写盘"。

## 5. 错误码 / 边界

| 情况 | 处理 |
|---|---|
| 文件不存在 | Rust 返 `Err("file not found: ...")`，UI 红条 |
| 空字符串 | 返 `Ok(PreviewResult { total: 0, importable: 0, skipped: 0, ... })`，UI 灰显 |
| 全是垃圾行 | 返 `Ok` + `skipped == total_lines`，UI "无有效数据" |
| settings_config 不是合法 JSON | 跳过该行 + 记 `reason: "settings_config invalid JSON"` |
| provider id 含非法字符 | 跳过 + 记 `reason: "invalid id (need [a-z0-9-_])"` |
| 写盘中途失败 | fs_atomic 已是原子的，已写的文件完整；后续文件不动（partial import）。ImportResult 返出错，UI 黄条。 |

## 7. 不做（YAGNI）

- 不实现 mcp.json 写盘（F6 范畴）
- 不做 import undo（F19 范畴；写盘前已自动 .bak.<ts>）
- 不做 provider 重复时覆盖（M2.2 保守策略 = 跳过；M2.3+ 可加"覆盖 / 改名"）
- 不做 SQL schema 解析（不 CREATE TABLE；只看 INSERT VALUES）
- 不解析 BEGIN/COMMIT/PRAGMA（直接丢弃非 INSERT 行）

# M2.8 F8 — 单文件部署 数据流

> **迭代**: M2.8
> **功能**: F8 单文件部署（NSIS installer + DMG + SHA256 校验和 + app metadata）
> **范围**: M2.8 = 工程交付层（生产级 installer 生成 + 元数据展示），不含自动更新（v1.1）

---

## 1. 业务定义

CLAUDE.md §1 明确："应用 = 一个可执行文件"。M1.x ~ M2.7 出的都是 dev build
（30 MB exe + WebView2Loader.dll，需要解压两个文件），**M2.8 把交付物升级
为生产级 installer**：

| 平台 | 工具 | 产物 | 用户体验 |
|------|------|------|---------|
| Windows | `tauri build --bundles nsis` | 单 .exe installer (~7 MB) | 双击 → 安装 → 桌面快捷方式 → 控制面板可卸载 |
| macOS | `tauri build --bundles app,dmg` | .dmg 镜像 | 拖拽到 Applications |

**与现有 dev build 的关键区别**：

| 维度 | dev build (M1.x ~ M2.7) | installer (M2.8) |
|------|------------------------|-----------------|
| 文件 | claude-config-manager.exe + WebView2Loader.dll | 单 .exe installer |
| 压缩 | 无 | NSIS LZMA |
| 安装 | 用户解压双文件 | 自动写入 Program Files + 创建快捷方式 |
| 卸载 | 用户手动删 | 控制面板 > 程序与功能 |
| 校验 | 无 | SHA256 |

## 2. 数据流

```
[F8 数据流 — 元数据查询]

User click "单文件部署" → setView('single-file-deploy')
  → SingleFileDeployPage mount
  → invoke('get_app_metadata')
  → Rust 返回 AppMetadata {
        version,         // env!("CARGO_PKG_VERSION")
        identifier,      // 编译期常量（与 tauri.conf.json 同步）
        product_name,    // 编译期常量
        git_commit,      // build.rs 注入的环境变量 BUILD_GIT_COMMIT
        build_target,    // std::env::consts::OS + ARCH
        build_timestamp, // build.rs 注入的环境变量 BUILD_TIMESTAMP (Unix epoch sec)
     }
  → UI 显示元数据卡片：
        ┌─ 当前应用 ─────────────────────────────┐
        │ 名称: ClaudeConfigManager              │
        │ 版本: 0.1.0                            │
        │ 标识: com.claudeconfigmanager.app      │
        │ 提交: 5b7ea6f (master)                 │
        │ 目标: windows / x86_64                 │
        │ 构建: 2026-06-19 10:30 (本地时间)      │
        └───────────────────────────────────────┘
```

```
[F8 数据流 — installer 生成（M2.8 阶段：仅 UI 引导，实际 build 在外部脚本）]

User click "查看 installer 生成命令"
  → 展开命令面板 (折叠/展开 by useState)
  → 显示三段命令文本（带"复制"按钮）：

      # Windows (NSIS, ~7 MB single-file)
      bash scripts/build-installer.sh windows

      # macOS (DMG)
      bash scripts/build-installer.sh macos

      # 验证 SHA256
      sha256sum -c installers/*.sha256

  → 副作用：installer 实际生成由外部 shell 触发（不在 Tauri 进程内）
  → 原因：tauri build 需 5-10 分钟 + 需 NSIS toolchain，不适合在主进程
    长期阻塞 + 无法可靠监听子进程 + WebView2 子进程模型限制
```

> **M2.8 设计原则**：UI 只展示 + 引导，不在 Tauri 进程内 spawn `tauri build`。
> M3+ 才考虑 background worker + 实时进度（需要 sidecar 模式）。

## 3. 编译期注入（build.rs）

`src-tauri/build.rs` 在 cargo build 时执行：

```rust
fn main() {
    // 注入 git commit (短哈希)
    let git_commit = std::process::Command::new("git")
        .args(["rev-parse", "--short", "HEAD"])
        .output()
        .ok()
        .and_then(|o| String::from_utf8(o.stdout).ok())
        .map(|s| s.trim().to_string())
        .unwrap_or_else(|| "unknown".to_string());
    println!("cargo:rustc-env=BUILD_GIT_COMMIT={git_commit}");

    // 注入 build timestamp (unix epoch sec)
    let ts = std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH)
        .map(|d| d.as_secs())
        .unwrap_or(0);
    println!("cargo:rustc-env=BUILD_TIMESTAMP={ts}");

    // 触发重编译当 HEAD 变化
    println!("cargo:rerun-if-changed=../.git/HEAD");
    println!("cargo:rerun-if-changed=../.git/refs/heads");

    tauri_build::build()
}
```

运行时 `env!("BUILD_GIT_COMMIT")` 拿到字面量字符串。

## 4. scripts/build-installer.sh

新建（**不动** scripts/build-and-ship.sh）：

- 输入：`windows` | `macos`
- 输出：`installers/<name>` + `<name>.sha256`
  - **不放在 `dist/`**：`dist/` 是 Vite 前端 bundle 输出，每次 `npm run build`
    会清空；而 `tauri build` 会先跑 `npm run build` 作为
    `beforeBuildCommand`，会把 `dist/` 下的产物清掉。`installers/`
    在 .gitignore 里，独立目录避免被清空。
- 不依赖现有 build-and-ship.sh（避免改动既有 dev 链路）

## 6. 不做（明确边界）

- 实时 build 进度条（需 sidecar，M3+）
- 自动签名（v1.1，需 EV cert）
- 自动更新通道（v1.1，updater plugin pubkey 已留位）
- macOS notarize（需真机 + Apple Developer 账号）

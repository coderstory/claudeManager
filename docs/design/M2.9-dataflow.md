# M2.9 — F18 配置优化数据流

## 目标

扫描 `~/.claude/` 下的配置文件,识别 13 类常见问题,提供"按需勾选 + 一键修复"的体验。每条修复都通过 `fs_atomic` 自动备份,可逆。

## 数据流

```
[F18 数据流]

User click 配置优化
  → setView('optimizer')
  → OptimizerPage mount
  → invoke('scan_optimizations')
       ↓
       OptimizerService::scan()
         1. 读 ~/.claude/settings.json (如不存在 = 空对象)
         2. 列 ~/.claude/providers/*.json (走 ProviderService::list_providers)
         3. 读 ~/.claude/mcp.json (走 McpService::list)
         4. 构造 OptimizerContext { settings, providers, mcp_servers, claude_dir }
         5. 遍历 13 个 OptimizerRule,每个 rule.check(ctx) → Vec<OptimizationFinding>
         6. 合并 + 去重(按 finding.id),按 severity (Error → Warning → Info) 排序
       ↓
  ← Vec<OptimizationFinding>
  → UI 渲染:13 类规则分组列表,每条带 checkbox + severity 图标
  → 用户勾选 → invoke('apply_optimizations', { findingIds: ['...', '...'] })
       ↓
       OptimizerService::apply_findings(ids)
         1. 重新 scan() 拿 findings(防止 ids 过期)
         2. 对每个 selected finding:
              a. rule = self.rules.iter().find(|r| r.id() == finding.rule_id)
              b. 调 rule.apply(finding, ctx)?  // 内部走 fs_atomic.write_with_backup
              c. 收集 ApplyResult { finding_id, applied, backup_path?, error? }
         3. 返回 Vec<ApplyResult> (即使部分失败也返回所有结果)
       ↓
  ← Vec<ApplyResult>
  → UI: 列表显示成功 / 失败 + 已备份路径
  → 用户可点 "重新扫描" 看修复后状态
```

## 13 条规则

| # | rule_id | severity | 含义 |
|---|---|---|---|
| 1 | ORPHAN_PROVIDER | warning | settings.json `env.ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` 引用的 provider 在 `providers/` 下不存在 |
| 2 | UNREFERENCED_PROVIDER | info | `providers/` 有的 provider 从未被引用过(`last_used_at` 空且不是当前 active) |
| 3 | DUPLICATE_MCP | warning | mcp.json 出现多个 server 共享同一 `command` 或 `url` |
| 4 | EMPTY_FIELD | warning | provider 的 `api_key` 或 `api_base` 为空字符串 |
| 5 | DEPRECATED_FIELD | info | settings.json 含旧字段 `claude_api_url` 或 `claude_api_key`(应迁移到 `env.ANTHROPIC_*`) |
| 6 | INSECURE_API_KEY | error | provider 的 `api_key` 长度 < 16 字符(明文短 token) |
| 7 | MCP_MISSING_TRANSPORT | warning | mcp.json 某 entry 缺 `command`(stdio)或 `url`(http) |
| 8 | LONG_PROVIDER_NAME | info | provider name > 50 字符(显示截断) |
| 9 | UNUSED_BACKUP | info | `<app_data>/backups/` 下 `.bak.*` 文件 mtime > 30 天 |
| 10 | LARGE_SETTINGS | warning | settings.json 文件大小 > 1 MB |
| 11 | MISSING_ACTIVE_PROVIDER | warning | settings.json `env.ANTHROPIC_BASE_URL` 缺失或为空 |
| 12 | DANGLING_ACTIVE_PROVIDER | error | `env.ANTHROPIC_BASE_URL` 不匹配任何 `providers/` 下的 provider |
| 13 | INCONSISTENT_PROVIDER_TYPE | info | `providers/` 下出现 "anthropic" + "Anthropic" + "ANTHROPIC" 等大小写混用 |

## 修复语义(`apply`)

| rule_id | 修复动作 |
|---|---|
| ORPHAN_PROVIDER | **手动**(返回 `applied=false, error="需用户决定:删 settings 引用 / 重建 provider"`) |
| UNREFERENCED_PROVIDER | **手动** |
| DUPLICATE_MCP | **手动** |
| EMPTY_FIELD | **手动** |
| DEPRECATED_FIELD | **自动**:从 settings.json 移除 `claude_api_url` / `claude_api_key` 字段(原 token 已经在 `env.ANTHROPIC_*` 里) |
| INSECURE_API_KEY | **手动** |
| MCP_MISSING_TRANSPORT | **手动** |
| LONG_PROVIDER_NAME | **手动** |
| UNUSED_BACKUP | **自动**:删除 mtime > 30 天的备份文件 |
| LARGE_SETTINGS | **手动** |
| MISSING_ACTIVE_PROVIDER | **手动**(用户去切换页) |
| DANGLING_ACTIVE_PROVIDER | **手动** |
| INCONSISTENT_PROVIDER_TYPE | **自动**:把 `provider_type` 全部 lowercase 后 atomic write provider JSON |

"手动" = `apply` 返回 `applied=false, error="..."`,UI 显示提示让用户去对应页面解决。
"自动" = 真正调 fs_atomic 改文件,成功返回 `applied=true, backup_path=Some(...)`。

## 类型契约

### OptimizationFinding

```rust
struct OptimizationFinding {
    id: String,              // uuid v4,每次 scan 重生成
    rule_id: String,         // "ORPHAN_PROVIDER" / etc
    severity: Severity,      // info | warning | error
    title: String,           // 给用户看的中文
    description: String,
    affected_path: String,   // 哪个文件 / 字段
    suggested_action: String,
    auto_apply: bool,        // 是否能自动修
}

enum Severity { Info, Warning, Error }

struct ApplyResult {
    finding_id: String,
    applied: bool,
    backup_path: Option<String>,
    error: Option<String>,
}
```

## 安全保证

- 所有自动修复经 `fs_atomic::write_with_backup`(CLAUDE.md §7),旧文件 → `*.bak.<ts>`
- `UNUSED_BACKUP` 删文件前不备份(因为本身是清理过期备份),但 30 天阈值是 hard-coded 防止误删
- 任何 rule.apply 失败不影响后续 finding(逐条独立 ApplyResult)
- 未知 finding_id → 返回 `applied=false, error="finding 已过期,请重新扫描"`

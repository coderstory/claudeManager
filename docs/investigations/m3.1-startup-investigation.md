## §2 现有启动链路（5 个时序点）

> **实测文件**（基于当前 master 分支代码，不是猜测）

### 时序点 (a) — `tauri.conf.json` splash 配置

- **文件**: `src-tauri/tauri.conf.json:21`
- **状态**: ❌ **无原生 splash 配置**（Tauri v2 的 `splashscreen` plugin 未启用）
- **现状**: `windows[0]` 只声明 `visible: true` + `transparent: true` + `decorations: false`，**没有 `splash` / `splashscreen` 段**
- **影响**: 启动时 Tauri 先创建 tao 窗口（transparent + 无边框），WebView2 初始化阶段（~50-200ms）显示**透明窗口 → 桌面壁纸透出 → 用户看到"全透明"**，然后 WebView2 加载 index.html 才显示 splash

### 时序点 (b) — `src-tauri/src/lib.rs::run` setup callback

- **文件**: `src-tauri/src/lib.rs:141-309`
- **关键步骤**:
  - `:141-143` `platform::init_for_runtime()` — 平台抽象初始化（轻量）
  - `:159-160` `AppState::build()` + `app.manage(state)` — 全局状态
  - `:194-202` `plugins::init_all` + `app.manage(Mutex::new(host))` — **D-槽1 改的 PluginHost wiring（18d4b29）**，12 stub 同步 init（no-op 但要走完 12 次注册 + log::info!）
  - `:204-216` deep-link plugin `on_open_url` handler + `handle_cli_arguments`
  - `:241-252` `pending_sql_file` 冷启动缓存写入 AppState
  - `:254-272` Tray icon 构建（**M1.1**,可能有 ~10-50ms 阻塞）
  - `:274-282` `on_window_event(CloseRequested)` minimize-to-tray
  - `:285-419` **`std::thread::spawn` + `sleep(200ms)` 后 apply Mica/vibrancy**（M2.16，异步路径）
- **问题**: setup callback 里 `init_all` 同步跑 12 stub 注册（虽然 no-op，但有 12 次 `log::info!` + Arc/Mutex 分配），加上 tray 构建 + setup 末尾 spawn 线程，**Tauri 在 setup 返回前不会 .show() main window**（其实 `visible: true` 已经在 tao 创建时显示）—— 但 setup 内部阻塞 = WebView2 还没机会解析 HTML。

### 时序点 (c) — `src-tauri/src/lib.rs` 启动 webview 时机

- **文件**: `src-tauri/src/lib.rs` 全局 + `tauri.conf.json:21-34`
- **现状**: `tauri.conf.json` 没有显式 `webviewOptions`，Tauri v2 默认行为是 setup callback 完成后**WebView2 立即开始 fetch index.html**
- **问题**: 没有 `WindowConfig::url` preload，没有 `webview.eval` 提前 warm-up。WebView2 cold start 才有 first paint（拉 index.html → 解析 → CSS → splash 显示）

### 时序点 (d) — `src/main.tsx` React 挂载

- **文件**: `src/main.tsx:25-32`
- **代码**:
  ```tsx
  ReactDOM.createRoot(document.getElementById("root") as HTMLElement).render(
    <React.StrictMode>
      <ThemeProvider>
        <App />
      </ThemeProvider>
    </React.StrictMode>
  );
  ```
- **现状**:
  - 主入口 import 了 `tokens.css` + `utilities.css`（影响 bundle 大小）
  - **无 Suspense fallback**（App.tsx 顶层不用 Suspense 包裹）
  - `<React.StrictMode>` 触发 double-render（开发模式更明显，release 也是双 effect 执行）
- **问题**: **无 Suspense** = lazy-loaded 子页（如果未来加 lazy()）会**整页空白**直到 import 完。本次 range 不动业务，但确认主树是同步 import，所以**不是根因**

### 时序点 (e) — splash 隐藏时机

- **文件**: `src/App.tsx:286-296`（顶层 useEffect）
- **代码**:
  ```tsx
  useEffect(() => {
    const splash = document.getElementById('ccm-splash');
    if (!splash) return;
    const hideTimer = window.setTimeout(() => {
      splash.classList.add('ccm-splash-hidden');
      window.setTimeout(() => {
        splash.style.display = 'none';
      }, 300);
    }, 2200);
    return () => window.clearTimeout(hideTimer);
  }, []);
  ```
- **现状**:
  - **固定 2200ms 延迟**（用户要求 splash 至少 2s + 200ms 余量）
  - 2200ms 后 add `ccm-splash-hidden` class → index.html 内联 CSS `transition: opacity 300ms ease-out`
  - 300ms 后 `display: none`
- **问题**:
  - **splash 显示时长 = 固定 2200ms，不管 React 是否 1s 内已经准备好**（用户能快看到主界面，但因为 splash 还在 2200ms 倒计时，**白屏 → 全透明 → loading 闪烁**的"loading 闪烁"感来自这个固定等待）
  - **没有基于 webview 真实 ready 事件**触发（应该用 `tauri://ready` 或 `window.__TAURI_INTERNALS__.metadata` 的 first-paint 信号）
  - **index.html 内联 splash 透明度固定 0.92**（CSS `background: rgba(250, 250, 247, 0.92)`），但 transparent 窗口 + WebView2 透明背景（`set_background_color(Color(0,0,0,0))`）= 窗口背后的 Mica backdrop 透过 splash 显示 → 视觉上 splash 显得"半透"（不是 loading spinner 的清晰视觉）

## §3 根因分析（4 候选，基于实际代码）

### 候选 A: **splash 透明度时序错位**（主修）

**证据**:
1. `tauri.conf.json:21-34` `transparent: true` + WebView2 `set_background_color(Color(0,0,0,0))` (lib.rs:331) → WebView2 完全透明
2. `index.html:73` splash CSS `background: rgba(250, 250, 247, 0.92)` —— 0.92 不是 1.0（near-opaque 但**有 8% 透明**）
3. `index.html:74-76` `backdrop-filter: blur(20px) saturate(180%)` —— backdrop-filter 在 transparent window 上渲染时机未确定
4. **WebView2 在 transparent window 上对 `backdrop-filter` 的合成路径与普通窗口不同**（DWM 合成 vs layered composition）→ backdrop-filter 在 cold-start 前 200ms 可能不生效

**结果**: 冷启动头 ~500ms 内，用户看到的是 **splash 半透明 + 后面 transparent webview + 桌面壁纸**的混合画面（白屏 → 全透明）。然后 backdrop-filter 生效变成 loading 画面（闪烁）

**代码位置**: `index.html:73-76`（splash CSS）

### 候选 B: **webview ready 事件未触发 splash 隐藏**（主修 - B 路径）

**证据**:
1. `src/App.tsx:288` useEffect 用 `setTimeout(..., 2200)` 固定延迟
2. **没有监听** `window.addEventListener('tauri://ready', ...)` 或 Tauri v2 `appEvent` 的 ready 信号
3. `index.html:175` failsafe 用 `setTimeout(..., 6000)` 兜底
4. 实际 React 挂载可能 500ms-1500ms 就完成（取决于机器）—— **splash 必须等到 2200ms 才淡出**，用户看到"白屏 + loading"不连贯

**结果**: 即便 React 早就 ready，主 UI 仍被 splash 盖住 2.2s。这是"loading 闪烁"的核心感。

**代码位置**: `src/App.tsx:286-296`

### 候选 C: **Suspense fallback + 异步加载冲突**（非主修）

**证据**:
1. `src/main.tsx:25-32` 没有 Suspense 包裹
2. `src/App.tsx` 所有页面 import 是**同步 import**（`import { HomeView } from './pages/home'` 等），不是 `React.lazy()`

**结果**: **不是当前根因**。本次修复 range 不加 lazy()（避免引入新问题）。

### 候选 D: **PluginHost init 12 plugin 阻塞**（次要）

**证据**:
1. D-槽1 commit `18d4b29` 加了 `init_all` 同步跑 12 stub 注册 + `log::info!`
2. `src-tauri/src/plugins/mod.rs:32-43` `init_all` 是 `host.init_all(ctx)` + `log::info!`
3. Stub `init` 是 no-op，但 12 次 `Arc::clone` + `Mutex::lock` + `HashMap` 插入 = **~1-3ms**（可忽略）

**结果**: **不是根因**（12 stub 注册 < 5ms，不构成可见阻塞）。但 D-槽1 加的 `app.manage(Mutex::new(host))` 是在 setup 里，影响 setup 返回时间。本次修复**保留** PluginHost wiring（不复盖 D-槽1 范围）。

## §4 修复方案（1 主修 + 1 polish）

### 主修: **候选 A + 候选 B 组合** — splash 透明度时序对齐 + ready 触发淡出

**改动文件**: 5 个（命中白名单）

| 文件 | 改动 | 行数估 |
|---|---|---|
| `src-tauri/tauri.conf.json` | 加 `splashscreen` plugin 声明（Tauri v2 splash image fallback）+ `visible: false` 启动时先隐藏窗口 | ≤10 行 |
| `src-tauri/src/lib.rs` | setup 里 emit `ccm://ready` 事件到 webview（webview 创建后立即 emit），而不是让 React 自己猜 2200ms | ≤20 行 |
| `index.html`（内联 splash CSS）| splash 背景从 `rgba(250,250,247,0.92)` 改为 `rgba(250,250,247,1.0)`（不透明），去掉 backdrop-filter（首帧无依赖），保证 cold-start 前 500ms 视觉一致 | ≤5 行 |
| `src/App.tsx` | useEffect 监听 `tauri://ready` 事件，ready 后**立即**隐藏 splash（带最小 800ms 兜底，保证用户至少看到 800ms loading）。index.html failsafe 改 4500ms（短于 6000，给 ready 事件更多容错）| ≤15 行 |
| `src/__tests__/components/splash.test.tsx` | 新 vitest 单测：mock `tauri://ready` 事件触发 splash 隐藏 | ≤60 行 |

**估时**: 2-3 小时（含 TDD red-green 循环）

### Polish: **候选 D 顺手** — PluginHost init log 改成 debug level

**改动文件**: `src-tauri/src/plugins/mod.rs`（**但这超出白名单，不改！**）

实际上 D-槽1 commit 已经把 PluginHost wiring 写完了，且范围与 M3.1 正交。**Polish 改为更直接的事**: `index.html` failsafe timeout 从 6000ms 改 4500ms（让 ready 事件真的失败时更快给用户反馈），**零行新增，纯改数值**。

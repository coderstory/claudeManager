## verify-first 核实清单 (phase 启动前必跑)

每个 phase 启动时,subagent 必须先跑这个核实脚本,确认 audit finding 还成立:

```bash
# 1. 看审计后哪些 audit 涉及文件被改过
AUDIT_BASELINE=89c944e  # round 1 汇总 commit
for f in <本 phase 涉及的文件列表>; do
  echo "=== $f ==="
  git log --oneline ${AUDIT_BASELINE}..HEAD -- "$f" | head -5
done

# 2. 重新 grep / 读 audit 引用的 file:line
# 3. 标记 RESOLVED-BY-DRIFT / 仍存在 / 行号变了 / 问题变了
# 4. 只对"仍存在"的 issue 写 fix plan
```

**任何 phase plan 不含 verify-first 步骤 → 不允许进入 execute-phase。**

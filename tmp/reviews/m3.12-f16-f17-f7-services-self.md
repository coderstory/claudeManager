## 设计选择
1. **Thin wrapper 模式**:旧方法签名保留(单参版本 delegate 到 `_with_active_root` 版本),command 层是唯一接入点。优点:既有的 34 个 test 0 修改通过;future 内部 helper 也能用旧签名;CLAUDE.md §3.2 分层原则(command 层负责 active_root 路由)
2. **mcp.json 不走 active_root**:`MarketplaceService::install_resource_with_active_root` 在 mcp 场景仍然返回 `installed: false`(M3.4 行为),active_root 路由只影响 file 落点,不影响"mcp 不自动装"这个决策
3. **cache 策略不变**:UsageService 5-min cache 仍按 `(provider_id, window)` 键;不同 `active_root_dir` 调用会自然 cache miss(因为 snapshot 内容不同)
4. **`detail` / `reveal` 不接 active_root**:F16 detail 只对 `path` 校验 `..` 穿越;reveal 是 platform trait 委托。两者不读 claude_dir,所以无需路由

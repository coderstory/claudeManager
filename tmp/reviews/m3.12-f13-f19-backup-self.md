## 关键安全决策: root 不存在拒绝还原 (不 mkdir) 的理由

1. **避免误写到未知路径**: 与 F18 apply_optimizations 同样的推理 — 用户切到 stale
   project (目录被外部 mv/rm), 服务应显式告知"root 不存在"而不是 silently mkdir。
2. **与 F18 安全边界对齐**: `optimizer_service.rs:178-191` 的 root-missing check 是
   M3.11 的高风险范式, backup 写路径必须跟齐。
3. **CLAUDE.md §7 "不允许静默吞错"**: 拒绝 + 显式 error message 满足此约束。
4. **新 variant `ActiveRootMissing(PathBuf)`**: 区别于 `PathNotAllowed` (allow-list 拒),
   也区别于 `Io` (真正的 I/O 错)。IPC 序列化为带 path 的可读错误, 前端可路由
   "项目目录不存在,请先创建或切换项目" 文案。

### `build_context` — settings_path 路由
```rust
let (settings_path, claude_dir) = match active_root_dir {
    Some(root) => {
        let proj_claude = root.join(".claude");
        (proj_claude.join("settings.json"), proj_claude)
    }
    None => {
        let sp = self.paths.settings_json.clone();
        let cd = self.paths.claude_dir()
            .map(|p| p.to_path_buf())
            .unwrap_or_else(|| self.paths.home.clone());
        (sp, cd)
    }
};
```

## 关键安全决策: root 不存在拒绝写 (不 mkdir) 的理由

1. **避免误写到未知路径**: 用户切到一个 stale 的 project (目录被外部 mv/rm),
   服务应**显式**告知"root 不存在"而不是"silently 创建一个空目录然后让
   DEPRECATED_FIELD rule 把空 settings.json 写成 {env: {...}}"。
2. **与写路径测试的意图一致**: 写路径是 high 风险, 必须 fail-loud。
3. **与 `IPlatformPaths::validate_backup_path` (windows/paths.rs:117) 行为对齐**:
   validate_backup_path 只 canonicalize 已存在的路径, 不创建 — 我们的 apply
   同样不创建未知 root。
4. **CLAUDE.md §7 "不允许静默吞错"**: 拒绝 + 显式 error message 满足此约束。

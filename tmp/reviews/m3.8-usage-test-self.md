## 边界 / 自审要点

1. **不引入子任务 4 的辅助函数到 service 代码**:
   `chrono_unix_humanlike` / `unix_to_iso_datetime` / `days_to_ymd` 三个
   helper 全在 integration test 文件里,**不**进 `src-tauri/src/`。M3.8
   service 里已有 `parse_rfc3339_to_unix` / `unix_to_iso_date`,但它都是
   private fn,本测试不耦合。

2. **fixture stage 模式 vs 直接读 fixture**:
   选了 `stage_fixture` (复制 fixture 到 `<tmp>/projects/<encoded>/<name>`)
   而不是 `compute_usage_from_jsonl` 直接传 fixture 目录。原因是
   `collect_jsonl_files` 要扫 `projects_dir/<project>/*.jsonl` 一级子
   目录,flat 目录会被跳过。复制模式保证 1:1 模拟 cc-switch 的 `projects`
   布局。

3. **unknown model 行为已验证**:
   `valid-5rec.jsonl` 的 model 名是 `claude-sonnet-4` / `claude-opus-4`
   (无日期后缀),builtin_pricing 表里只有 `claude-sonnet-4-20250514` 等
   带日期版本 → cost=None 但 token 计入。子任务 3 验证了这个 SUMMARY
   提到的设计决策。

4. **5h 窗口边界**: 子任务 4 用了 6h ago (21600s) 验证 5h 窗口的 hard
   exclude,断言 9999+9999 不会被加到 5h 窗口结果中。

5. **未触碰 service / fixtures**:
   - `services/usage_service.rs` 0 changes
   - `services/usage_provider_ccswitch.rs` 0 changes
   - `tests/fixtures/m3-8-usage/*.jsonl` 0 changes
   - 只新增/扩充 `tests/m3_8_usage_ccswitch.rs`

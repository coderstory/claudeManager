# M4.6 WindowChrome 架构统一 — 自审报告

## 改动概览
- 修改文件: 3 个
  - `src-tauri/src/platform/macos/window_chrome.rs` — no-op → real apply_vibrancy (compile on macOS, cross-compile stub on Windows)
  - `src-tauri/src/platform/mod.rs` — `window_chrome()` factory 接受 `&WebviewWindow` 参数
  - `src-tauri/src/lib.rs` — 移除 `#[cfg]` 块，改为 trait dispatch
- 未修改: `windows/window_chrome.rs`, `traits.rs`, 任何前端/业务代码

## 逐文件逐行审查

### 1. platform/macos/window_chrome.rs
**变更**: `MacWindowChrome` 从零大小结构体变为持有 `tauri::WebviewWindow` 的结构体。
- ✅ `#[cfg(target_os = "macos")]` gate 正确——只在 macOS 目标上调用 `apply_vibrancy`
- ✅ 交叉编译桩 `#[cfg(not(target_os = "macos"))]` 返回 Ok(())，不影响 Windows dev box
- ✅ `apply_vibrancy` 错误映射为 `PlatformError::Other`，不吞错
- ✅ `mica` / `title_bar_style` 显式忽略（`let _ =`），文档清晰
- ✅ 测试只做编译期断言（无法构造真实 WebviewWindow），不引入 false confidence
- ⚠️ 无法在 Windows 上验证 `apply_vibrancy` 真实路径（D6 Mac 真机验证不在本次范围）

### 2. platform/mod.rs
**变更**: `window_chrome()` 从无参变为接受 `&tauri::WebviewWindow`。
- ✅ Windows 分支忽略参数（`let _ = window;`），行为与旧版一致
- ✅ macOS 分支 `window.clone()` 传入 `MacWindowChrome::new`——符合 Tauri 所有权模型
- ✅ 返回值类型 `Box<dyn IPlatformWindowChrome>` 不变，所有调用方不需要改

### 3. lib.rs
**变更**: 移除 ~25 行 `#[cfg(target_os = "windows")]` / `#[cfg(target_os = "macos")]` 块，替换为 10 行 trait dispatch。
- ✅ `WindowChromeOptions` 构造正确: `vibrancy: true, mica: true, title_bar_style: Transparent`
- ✅ `runtime::window_chrome(&window_for_effect)` 把 Window 句柄注入工厂
- ✅ `chrome.apply(&opts)` 通过 trait dispatch 派发到正确的平台实现
- ✅ 错误日志 tag 从 `[M2.16]` 更新为 `[M4.6]`，确认无误
- ✅ `std::thread::spawn` 内部的 `window_for_effect` clone 仍然有效（spawn 前 clone）
- ✅ 不再直接引用 `window_vibrancy` crate——lib.rs 不再需要 `window-vibrancy` 依赖（但 Cargo.toml 保留它，因为 macOS window_chrome.rs 需要；Windows 分支路径通过 `cfg` gate 不会编译到它）
- ✅ 消除了 CLAUDE.md §3.2 违规："lib.rs cfg 块绕过 window_chrome trait"

## 边界/并发分析
- ✅ `std::thread::spawn` 内部: trait dispatch 在 spawn 后执行，Window 句柄通过 clone 传递，线程安全（`WebviewWindow` 是 `Send`）
- ✅ 工厂返回 `Box<dyn IPlatformWindowChrome>` 在 spawn 内部临时构造，spawn 结束后 drop
- ✅ 无跨线程共享状态——每个 spawn 独立构造自己的 chrome impl

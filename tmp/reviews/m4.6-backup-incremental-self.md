## Design decisions

| Decision | Rationale |
|---|---|
| "Incremental" = skip identical snapshots (not byte-delta storage) | JSON config files < 100KB; full snapshots cheaper at restore and easier for user timeline |
| Compare `original_name` match + byte-for-byte content | No hash overhead; `list_backups` is sorted newest-first, so first hit = most recent |
| No mtime/hash dependency | std::fs::read_to_string + `==` comparison is fast enough for config-size files |
| `BackupError::NoChange` is an error variant (not an `Ok` sentinel) | Forces command caller to handle distinctly; Rust `Result` semantics are clearer than sentinel values |
| `backup_incremental` falls through to `backup_now()` for new snapshots | Reuses existing atomic-copy + scanner-parse path, zero new I/O code |

## Test coverage

| Scenario | Test | What it proves |
|---|---|---|
| First backup (no previous) → creates new | `backup_incremental_first_time_creates_new_backup` | No prior backup = must create (same as `backup_now`) |
| Previous exists + content changed → creates new | `backup_incremental_when_changed_creates_backup` | Only 1 changed file → new snapshot, different path |
| Previous exists + content unchanged → NoChange | `backup_incremental_unchanged_returns_no_change` | Timline stays clean; duplicate is skipped |

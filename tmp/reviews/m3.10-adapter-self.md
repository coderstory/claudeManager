## 自审

### Bug 检查
- [x] 所有 helper 是 additive,旧签名 `list_providers` / `switch_provider(id)` 完全保留 — 不会破坏现有调用方
- [x] `switch_provider_with_active_root` 在 `Some(p)` 模式时,正确解析到 `<p>/.claude/settings.json` 而非 `paths.settings_json`
- [x] `None` 模式 = 旧路径 = 完全向后兼容(测试 `*_none_matches_legacy` 覆盖)
- [x] Provider library 文件 (`<app_data>/providers/<id>.json`) 在两种模式下都走同路径(库是用户级资源,只有"激活的 provider" 状态跟项目模式挂钩 — 这是产品决策,已在 doc 里说明)

### 边界 / 失败模式
- [x] 不存在的项目根 → Io error(fs_atomic 写盘失败冒泡)
- [x] `active_root_dir()` 返回 None(用户级) → fallback 到 `paths.claude_dir()` / `paths.settings_json`
- [x] `active_root_dir()` 返回 Some 但 `.claude/` 子目录不存在 → 第一次写 settings.json 时父目录不存在,fs_atomic 失败(给用户可见错误,符合 §6.5)

### 并发
- [x] 所有改动是纯函数(无新增 mutable state,无锁)
- [x] `active_root_dir()` 由 `runtime::paths()` 返回 `Box<dyn IPlatformPaths>`,Windows 实现读磁盘,无内部状态

### 平台差异
- [x] macOS: `MacPaths::active_root_dir()` 始终返回 `None`(per M3.10 §7 决策 6: compile-only stub),所以 mac 上 `switch_provider_with_active_root(None, ...)` 永远走用户级 — 完全等价旧行为
- [x] Windows: `WindowsPaths::active_root_dir()` 读 `projects.json`,行为如 spec

### 文档一致性
- [x] 3 helper 的 doc-comment 解释 M3.10 适配目的
- [x] `switch_provider` command doc 标注 M3.10 adapter
- [x] 写 `docs/design/M3.10-adapter-phase1.md` 报告 3 high 适配点

### 集成测试
- [x] 端到端: `switch_provider_with_active_root_writes_to_project_claude_dir` 验证项目模式写盘到项目根且不影响用户级
- [x] 切换场景: `allowed_directories_expand_with_active_project` 验证 None → Some 时 allow-list 扩展

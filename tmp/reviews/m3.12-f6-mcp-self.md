## 关键设计决策

### 1. `with_root()` 而非直接修改 `state.mcp_service` 字段

为什么用 `with_root(Option<&Path>) -> McpService`(返回新实例)而非:
- (a) 给 `AppState` 加 setter — 改 `AppState` 公共接口,影响所有 plugins
- (b) 每次 command 内部构造 `new_with_active_root` — 命令层重复 `let paths = state.paths.clone();` 模板代码

`with_root` 是 (b) 的封装版:`self.paths.clone()` + 新 root → 新 `McpService`。`AppState` 仍是 `Arc<McpService>`(M2.5 起的契约不变),命令层每次拿一个**轻量派生实例**用完即弃,与 F18 `scan_with_root(active_root_dir)` / `apply_findings(...)` 同源模式。

### 2. `write_all` 安全边界:`Some(root)` + `!root.exists()` → 拒绝写,不 mkdir

与 F18 `apply_findings` line 178-191 完全同源(参照 commit `2e4e75b`)。理由:
- **CLAUDE.md §7**: "任何写盘操作必须先备份" — 拒绝写入不存在的目录避免了"备份到一个不存在的目录"这种荒谬路径
- **CLAUDE.md §2.4**: "禁止猜测哪个文件该改" — 用户没显式建立 project root,我们不能擅自 mkdir 出一个用户未授权的目录结构
- **F18 已确立的模式**: `apply_findings` 也是相同语义,跨 plugin 一致
- **错误信息**: `"active root 目录不存在: {} (拒绝写入,避免 mkdir 未知路径)"` 与 F18 措辞完全一致,跨 plugin 错误体验统一

读路径**不**检查 root 存在:`list_with_warnings` 已支持"文件不存在返回空 Vec",`Some(root)` + `<root>/.claude/mcp.json` 不存在时直接返回空列表 — 这与 F18 `scan_with_root` 一致(读宽容,写严格)。

### 3. 构造器双轨:`new()` (向后兼容) + `new_with_active_root()` (新)

`McpService::new(paths)` 内部 delegate 到 `new_with_active_root(paths, None)`。所有现有调用点(`AppState` 构造、Tauri builder 注册)不需要改 — `active_root_dir` 默认 `None`,行为完全等同 M2.5。这保证了:
- 现有 `McpService::new(paths)` 调用点零改动
- 现有所有 `McpService` 测试(`list_empty_file_returns_empty_vec` 等)零改动
- `parse_mcp_deeplink` 不依赖 `McpService`,不动

### 4. `McpError::Io(NotFound)` 包装

直接用 `McpError::Io(std::io::Error::new(ErrorKind::NotFound, "..."))` — `McpError::Io` 已有 `#[from] std::io::Error`,所以可以直接构造。错误信息带具体 root 路径,前端拿到 stringified error 后能在 InfoBar 直接展示。

## 测试覆盖 (TDD — 4 个场景)

所有新测试在 `services/mcp_service.rs` 文件末尾的 `#[cfg(test)] mod tests` 内追加,**不**重写现有测试。

### Helper: `build_svc_with_root(tmp, active_root) -> (McpService, user_mcp_path, Option<project_mcp_path>)`

参照 F18 `optimizer_service.rs::build_svc_with_root` (line 568-594) 模式:
- 始终建一个 "user" 目录模拟用户级 `~/.claude/mcp.json`
- 当 `active_root = Some(p)` 时,返回 `Some(p/.claude/mcp.json)` 作为 project mcp 路径
- 测试 caller 自己决定是否预先建 root + 写文件(场景 4 ghost root 不预建)

### 场景 1: `active_root = None` + 读 → 用户级 mcp.json (向后兼容)

`read_with_active_root_none_reads_user_dotclaude_mcp_json`:
- 写 `<user>/.claude/mcp.json` 含一个 server
- `McpService::new_with_active_root(paths, None).list()` → 1 个 server,名字匹配
- 验证 M2.5 行为不变

### 场景 2: `active_root = Some(root)` + 读 → `<root>/.claude/mcp.json`,**不**读用户级

`read_with_active_root_some_reads_project_mcp_json_not_user`:
- 用户级 mcp.json 含 `user-only`
- project-level mcp.json 含 `proj-fs` + `proj-remote`
- `service.list()` 返回 2 个 project server,**不**含 `user-only`
- 验证路径已切换、用户级不泄漏

### 场景 3: `active_root = Some(root)` + 写(add) → project mcp.json + atomic backup

`write_with_active_root_some_writes_to_project_and_creates_backup`:
- 预建 `<project_root>/.claude/`,预写一个 server `old` 到 project mcp.json(让 backup 有内容可备份)
- `service.add("new-proj")` 成功
- 验证:
  - project mcp.json 含 `"new-proj"`,**不**含 `"old"` (新内容已写入)
  - `<project_root>/.claude/mcp.json.bak.<ts>` 存在 + 含 `"old"`(atomic backup 保留旧内容)
  - 用户级 `<user>/.claude/mcp.json` **不**存在(没被动过)

### 场景 4: `active_root = Some(root)` + root 不存在 → 拒绝写,不 mkdir

`write_with_active_root_some_missing_root_rejects_no_mkdir`:
- `ghost_root = tmp/ghost-project` **从未**创建(`!exists()`)
- `service.add("ghost")` 返回 `McpError::Io(_)`(匹配 `NotFound` kind)
- 验证:
  - `ghost_root.exists() == false`(没被 mkdir)
  - `project_mcp_path.exists() == false`(没被建)
- 这就是 CLAUDE.md §7 安全边界的端到端 pin

## 业务流程分析 (CLAUDE.md §6 第 4 步)

完整 user journey: 用户在 M3.10 项目切换器选了某个 project → `projects.json` 写入 `current_project_id` + `root_dir` → 后续每次 F6 UI 调 `list_mcp_servers` / `add_mcp_server` / etc:

1. `invoke('list_mcp_servers')` → `commands/mcp.rs::list_mcp_servers`
2. `let active_root = crate::platform::runtime::paths().active_root_dir();` → 读 projects.json(平台层,本命令 0 改动)
3. `state.mcp_service.with_root(active_root.as_deref())` → 派生新 `McpService`,mcp_json_path 切到 `<active_root>/.claude/mcp.json`
4. `list()` → 读 project mcp.json
5. 写操作(add/toggle/update/remove)先校验 root 存在(场景 4 拒绝),然后走 `fs_atomic::write_with_backup` 写到 project mcp.json + atomic backup

**断点检查**:
- 用户切回 user-level(active project 清空) → `active_root_dir() = None` → 走 user-level `~/.claude/mcp.json` (场景 1 保证)
- 用户选的 project root 还没建 `.claude/` → 读返回空列表(场景 2 不报错),写拒绝(场景 4)
- 用户切的 project 在另一个 drive / 不存在 → 写拒绝 + 友好错误信息(场景 4)
- 用户快速切 project → 每次 invoke 重新读 `active_root_dir()`,并发安全(命令层无锁,服务层是只读派生)

**未在本次范围**:F6 UI 暂未联动 project switcher(后续 M3.13+ 迭代)。本次 backend 接入完成,UI 切 project 后调 `invoke('list_mcp_servers')` 就能立即看到 project-level MCP 列表。
